# Правила для ИИ-агентов (Claude, Codex и любых других)

Здесь только то, что нужно с первой минуты. Большие документы целиком не
читать: один хендофф больше 200 КБ и съедает контекст до первой строки кода.
Открывать их по ссылке из задания и только нужный раздел.

## Где что

- Карта проекта: `КАРТА-ПРОЕКТА.md`. Текущее состояние: верхние разделы
  `docs/GLASS_ERP_HANDOFF.md`. Станочный экспорт: `docs/MACHINE_EXPORT_STATUS.md`.
- Код — модули в `src/`, порядок подключения — `build/manifest.json`.
  `dist/GLASS_ERP.html` и `src/index.html` собираются из модулей, руками
  их не правят.
- Код пишут параллельно Claude и Codex. Состояние сверять с `origin/main` и
  `gh pr list`, а не с локальной копией: она бывает старше.

## Codex, ChatGPT и другие модели

- Первым прочитать раздел «Как вести себя с проектом» в начале
  `docs/ДЛЯ_ЧАТГПТ.md`: вникнуть до кода, причина вместо симптома, вся
  документация, честный PR.
- Раскрой (`cut-layout*.js`, `cut-machine-*.js`, `test/cut-layout.js`) не
  правят: этот раздел ведёт Claude с владельцем. Нашёл проблему — описать.

## Правила продукта

- Интерфейс только на английском: никакого русского в разметке,
  `alert`/`confirm` и текстах ошибок. Тесты это проверяют.
- Подсказки в интерфейсе — несколько слов.

## Как писать код

- Проще: ровно то, что просили. Без функций «на будущее», лишних обёрток
  и настроек, которых никто не просил.
- Точечно: правь только то, что нужно для задачи. Соседний код не
  переделывать и не «улучшать» попутно; нашёл там проблему — опиши её.

## Ветка и PR

1. Ветка от свежего main:
   `git fetch origin && git checkout -b <имя> --no-track origin/main`.
   Без `--no-track` upstream ветки — `origin/main`, и пуш из
   `tools/prepush.js` отказывает.
2. `npm ci` в каждом новом worktree и после смены версии Playwright в
   `package.json`: `node_modules` не общий. У Claude это делает хук при старте
   сессии (`.claude/settings.json`).
3. Новый файл модуля — в `build/manifest.json`. После любой правки в `src/`
   — `npm run build:web` и закоммитить `src/index.html`: в нём метка сборки,
   она меняется вместе с модулями.
4. `dist/GLASS_ERP.html` в ветку не коммитят: его пересобирает CI в main
   после слияния (коммит «Автосборка после правки модулей»).
5. Добавил или убрал проверки в `test/run.js` — поправь число проверок в
   первом абзаце `README.md`: тест сверяет его с настоящим.
6. Поведение изменилось — новый раздел сверху в `docs/GLASS_ERP_HANDOFF.md`.
7. Пуш: `node tools/prepush.js` — догоняет main, гоняет все проверки и
   тесты, пушит. `--dry` — то же без пуша.
8. PR: `gh pr create --base main --head <ветка>` — оба ключа явно.

## Проверка

- Правка раскроя: ещё `node tools/cut-bench.js` — батчи владельца против
  Perfect Cut; листов не должно стать больше ни на одном. Данные только на
  машине владельца (путь в `~/.glass-erp-cut-bench`), в Git их не класть.
- `npm run test:snap` — тесты по копии последнего коммита (2–3 мин), рабочее
  дерево тем временем можно править. `npm run test:snap -- --dist` — ещё и по
  собранному файлу. Незакоммиченное в прогон не попадает.
- `npm run shot -- --data latest --tab sales` — PNG «сейчас (main) / после
  (ветка)» с последней выгрузкой владельца из `~/Downloads`. Владелец
  проверяет правки по таким картинкам. Все ключи: `node tools/shot.js --help`.
- Просмотр в браузере: `node tools/preview-server.js` →
  http://127.0.0.1:8765/src/index.html. Другой корень (копия коммита) —
  путь в `.preview-root` или `PREVIEW_ROOT`; `.claude/launch.json` не править.
- Выгрузки владельца (`glazing_system_data*.json`) — рабочие данные цеха.
  Репозиторий публичный: в коммиты их не класть.
- Цех на большом объёме: `node tools/sim-shop.js` — 14 месяцев работы цеха
  функциями ERP (заказы, батчи с раскроем, сканы по сменам, отгрузки, оплаты)
  и «правильные ответы» для отчётов; `--small` — малая база, которая влезает
  в браузер; `--check` — отчёты конструктора против ответов и время экранов
  (есть ✗ — код выхода 1);
  `--inventory` — ещё и склад (закупки, приёмки, пересчёт, Offset, куски S-);
  `--guide` — заказы на каждом этапе и путеводитель `<name>-guide.md`;
  `--ndjson` — итог построчным Export v2, `--snap 3,6,12` — ещё и снимки
  базы после N месяцев. Выход — `~/.glass-erp-walk/sim`, в Git не класть.
- Скорость на годе: `node tools/perf-year.js <база> --name year --required` —
  Import, F5, все экраны и действия, вторая вкладка, память; два прохода,
  второй — процессор ×4 (слабый ПК). Пороги владельца на ×4 (28.10.2026 —
  свой у каждого действия): скан ≤ 1 с, действие офиса (Save, Convert,
  батч, правка листа, PS, Shipped, оплата) ≤ 5 с, экран ≤ 1 с, F5 ≤ 5 с,
  память ≤ 1 ГБ; ✗ — код выхода 1. Запускать перед крупными PR и раз в месяц. Базы:
  `node tools/sim-shop.js --inventory --start 2024-10-01 --end 2026-09-30
  --name year2 --ndjson --snap 3,6,12` (24 месяца, ~2 ч). Выход —
  `~/.glass-erp-walk/perf/<дата>-<имя>/report.md`, в Git не класть.
  Без `--archive` весь год в памяти (в цеху так не бывает): мерить оба режима.
  Ускорение принимать по двум итогам: `--compare <папка прошлого прогона>` —
  контрольные ответы (строка каждого заказа из Sales) те же, и тот же
  сценарий быстрее. С архивом: `--archive <YYYY-MM-DD>` — уход в архив на
  этот день после Import и сверка ответов «до / после»; `--years 7` — ещё и
  архив, размноженный на прошлые годы (год: `year2-12m.ndjson --archive
  2025-09-30 --years 7`, ~25 мин).
