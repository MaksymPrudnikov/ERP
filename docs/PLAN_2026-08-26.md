## 1. Что уже нельзя переигрывать

### Production Shape / DXF

- Fusion 360 — источник внешнего DXF для раскроя.
- Сырой DXF в `localStorage` не хранится.
- Production Shape хранит лёгкий производный preview contour + file metadata + bounding Width/Height.
- DXF пользователя приходит в inches; CNC сам работает с mm.
- Sales dimensions округляются до ближайшей `1/16″`.
- Billable Shape area = bounding `Width × Height / 144` ft².
- Manufacturing overlay никогда не меняет Cutting Shape / Cutting DXF.

### Manufacturing items

- Hole — только внутри Shape, позиция до центра: Left/Right + Top/Bottom, шаг `1/16″`, на drawing две размерные цепочки + Ø.
- Clamp / Hinge — только на finished edge. Left/Right считаются от bottom corner; Top/Bottom — from left corner.
- Items видны на Production Drawing и дают Manufacturing requirements / commercial charges.
- Items не входят в Cutting Geometry / machine payload.
- Quantity выводится из реальных items и не редактируется вручную ради цены.

### Pricing

- Геометрия, inches, area, edge length, item quantity — **read-only для pricing**.
- Пользователь редактирует только денежную ставку цифрой. Процентных скидок нет.
- Приоритет effective rate: **LINE → ORDER → CATALOG**.
- Order-wide edit применяется ко всем одинаковым charges заказа.
- Line override — исключение одной строки.
- Final total = calculated basis × Sales line Qty × effective rate.
- Catalog rate snapshot сохраняется в заказе. Старый заказ не должен перепрайситься после изменения текущего каталога.
- Missing rate ≠ `0`. UI обязан показывать `Rate required / Pricing incomplete`.

### Operations vs Services

Владелец уточнил реальную бизнес-модель:

- `DB.operation` = производственный маршрут (`CUT / EDGE / FAB / HEAT / ...`).
- Billable service = коммерческое начисление клиенту (`Clamp / Hinge / Hole / Polish / Miter / ...`).

Не пытаться снова использовать `DB.operation` как прайс сервисов. Это разные сущности.

## 2. Главная задача дня — настоящий Service Catalog

Сейчас подтверждённые standard rates временно лежат в Sales pricing-коде. Это нужно заменить отдельным источником правды для коммерческих сервисов.

### Нужная модель

Минимальная запись Service Catalog должна позволять хранить:

- стабильный `id`;
- `code`;
- RU/EN display name (или нейтральное рабочее английское имя, если так принято в цеху);
- category: manufacturing item / edge processing / shape feature / glass finish / IGU / other;
- pricing basis: `pc`, `inch`, `sqft` (только подтверждённые единицы);
- thickness pricing bands / rules;
- active/inactive;
- source mapping: из какого факта ERP charge формируется автоматически;
- note.

**Не заводить вторую копию цен внутри Shape.** Shape хранит факт/геометрию; Service Catalog хранит standard rate; Sales Order хранит snapshot + overrides.

Если новый JS-модуль создаётся — добавить его в `build/manifest.json` и `src/index.html` в одинаковом порядке. Если Service Catalog помещается в существующий sales/masterdata data-module без смешения доменов, новый файл не обязателен.

## 4. Старый прайс — сначала ревью, потом код

В старой таблице владельца есть ошибки, устаревшие строки и позиции, которые вообще не должны быть ручными Services. Не переносить всё автоматически.

### Группа AUTO — цена должна появляться из уже выбранной геометрии/настройки

Кандидаты:

- High Flat Polish → Edge Processing;
- Rough Arris → Edge Processing;
- CNC Shape Polish → Edge Processing;
- Mitering 22.5° → Edge Processing;
- Radius Corner → Shape feature;
- CNC Notch / Outlet cutout → только после подтверждения модели начисления.

Пользователь не должен выбирать этот же service второй раз руками, если ERP уже видит его из Shape. Иначе будет double charge.

### Группа REVIEW — не кодировать цену без ответа владельца

- Mitering 45°;
- Beveling и все старые bevel rows;
- generic `CNC Processing`;
- CNC Notch / Outlet cutout pricing semantics;
- Notches by Hand;
- CNC Laminate;
- Polish Lami Glass;
- Extra Charge for IGU Shapes;
- Edge Sealant;
- Heat Soak Test rows;
- Mirror Safety Backer;
- Backpainting;
- Sandblasting;
- Consumables (spacer / argon / muntin bar) — это отдельная модель от per-piece Shape services.

Спросить владельца **одной пачкой**, не по одному вопросу.

## 6. После Service Catalog — Hardware Library

Только после принятого каталога начинать библиотеку реальной фурнитуры.

Будущая логика должна позволять:

`specific hardware item → Manufacturing item(s) → commercial Service(s) → production note/prep`

Например, конкретная hinge позже может потребовать набор подготовок. Не предполагать сейчас шаблоны отверстий/notch — владелец должен дать реальные hardware/templates.

Важно: Hardware Library не должна менять внешний Cutting DXF автоматически. Fusion 360 остаётся источником файла раскроя, пока владелец явно не изменит этот контракт.

## 8. Acceptance / safety gates

Перед каждым PR:

1. `node build/check-manifest.js`;
2. сборка `dist` через `build/build.js`;
3. `TARGET=dist node test/run.js` в GitHub Actions;
4. alert / confirm / `throw new Error` только English;
5. EN проход без кириллицы вне `data-raw`;
6. user data только `raw()` / `data-raw`;
7. existing v4.5 Shape geometry numbers не менять;
8. Muntin pinned revision contract не менять;
9. pricing tests должны доказывать, что rate edit не меняет Shape geometry, dimensions, edge lengths или item counts;
10. missing catalog rate никогда не становится молчаливым `0 CAD`.
