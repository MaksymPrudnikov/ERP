## Зачем

1. **Карта цеха.** Сейчас Production показывает цех таблицами и плитками. Не видно, где что стоит, какая
   станция сейчас работает, где копится стекло и где стоит тара. Нужен вид цеха целиком, по плану помещения.
2. **Волна 2 «агенты в ролях».** Офис, оптимизатор и главные работники проходят свою работу в настоящей ERP и
   пишут, чего им не хватает. Потом фильтр: где мы «прозевали», а где не стоит слушать. Волна 1 была 11.10.2026
   (`tools/sim-shop.js`, агенты в ролях оптимизатора, продажника, CUT, Shipping, бухгалтера →
   `test/sim-walk-fixes.js`). Теперь — повторяемый инструмент и правило фильтра.

Задачи связаны: агенты проходят ту же ERP, которую карта показывает. Сканы `DB.stationScan` — общий поток
событий, новой схемы событий не нужно.

## Решения владельца в чате (19.11.2026)

- **Где**: офисная ERP, Production → новая таблетка **Floor** рядом с In production / Stations / Terminals /
  Dollies & Skids. На экранах станций Floor нет.
- **Вид** — «живой макет архитектора»: аккуратно, «со вкусом, не убого», без деревьев и декора, только
  производство. **По умолчанию 2D**, 3D — по необходимости, с поворотом мышью («чтобы можно было покрутить»).
- **Размещает и меряет владелец сам**, в метрах: «полировка 2 × 6 м, а завтра померяю — окажется 7». Сам ставит
  станции, подписывает, двигает и вписывает точные размеры.
- **Стены, скиды и прочее** — тоже на карте. Долли и скиды рисуются сами у станции, где их стекло.
- **Мало кнопок** («кнопок много, спрятать лаконично»). **Текст не налезает** («более культурно»).
- **Не весит и не тормозит работу.**
- **Клик по станции — показатели за сегодня**, и **с разбивкой по датам** («не только за день»).
- **Цвета самой ERP** (`src/styles/tokens.css`), светлая и тёмная тема.
- **Общей линии маршрута нет** («чей флоу показываем, если некоторые скипнутые?»). Вместо неё — потоки
  выбранной станции (см. A2).
- **Потом**: вызов мастера со станции, станция горит красным (часть C).
- **Перемотки времени нет**: владелец её не просил, а подмена сканов в памяти рядом с записью может их стереть.

## Часть A. Production → Floor

### A1 (PR). Данные и редактор

**Таблица** `DB.floorItem` (`DEFAULT.floorItem=[]` в `src/erp/production/floor.js`), строки
`{id: crypto.randomUUID(), kind, station, label, x, y, w, l, h}`, метры, два знака.
- `kind`:
  - `hall` — одна строка, размер зала;
  - `machine` — станок станции (у станции может быть несколько, POLISH — 3);
  - `wall`;
  - `object` — стеллаж, пирамида, стол, колонна;
  - `area` — зона; может быть привязана к станции, тогда в ней стоят её скиды;
  - `spot` — место долли станции.
- Нормализатор: плохие числа → безопасные, размеры ≥ 0.1. Вызов — в явном списке `normalizeDB` (`storage.js`).
- Поворота как поля нет: `Rotate 90°` меняет местами ширину и длину.
- id — `crypto.randomUUID()`, как `viewProfileId` (`data.js`).

**Старт**: таблица пустая (`test/base-start`, `test:snap` не меняются). В Edit кнопка `Start from sketch` заводит
зал, стены и блоки наброска неподписанными, дальше Save. Сам нормализатор ничего не заводит: иначе два ПК завели
бы план дважды.

**Редактор** (`Edit`, только у кого галочка Master Data):
- полоса `Editing · Save · Cancel`;
- правка в 2D: перетаскивание с шагом 0.1 м, стрелки 0.1 / Shift 1 м;
- поля `Station`, `Label`, `X`, `Y`, `Width`, `Length`, `Height`; `Add…` (Machine, Wall, Object, Area,
  Dolly spot); значки `Rotate 90°`, `Duplicate`, `Delete`; `Hall W × L`; список «Not placed».
- Наложение блоков или выход за зал — жёлтая полоса `Overlaps POLISH`; Save не блокируется («без кирпичей»).
- Запись — только `floorSave` (имя подходит под `storageLockButtons`), одна `storageCommand`.
- Черновик — в `STORAGE_UNSAVED`. Фоновый `render()` после синхронизации не сбрасывает черновик и
  перетаскивание.
- **Переименование станции** (`saveSfStation`, `views/production.js`) правит `floorItem.station` той же
  командой. Если код пропал — блок помечен `Unknown station`.

**Права на сервере**: у `floorItem` нет правила `erp_table_rule`, как у большинства таблиц (решение владельца
26.10). Галочка закрывает правку в интерфейсе; закрыть на сервере — Users → Cloud → Access.

### A2 (PR). Состояние, 3D, карточка станции

**Состояние станции** — из `prodBoard()`: `counts` (ждёт) и `onAt` (какие долли и скиды).
- **Working** — неотменённый скан станции за последние 15 мин.
- **Waiting** — стекло ждёт, сканов нет.
- **Idle** — остальное.

Тара рисуется сама: в `spot` или `area` своей станции, иначе рядом с первым станком. У SHIPR / SHIP — скиды.

**Цвета — только ERP** (`tokens.css`; новых нет, это проверяет `test/design-tokens.js`). Тема — та, что
выбрана в ERP.
- Working — `--success`; Waiting — `--warning`; Idle — `--surface*` / `--line*`.
- `--danger` — только вызов мастера (часть C).
- Пол — `--surface`; выбор и стрелки потоков — `--accent`.
- Стекло на долли — `--cut-glass-*`, скид — `--series-11`.

**Потоки выбранной станции** — вместо общей линии маршрута. Клик по станции рисует стрелки к соседним станциям,
толщина и число — сколько стекла:
- **«Пришло отсюда»** — у стекла, что ждёт здесь, станция последнего скана;
- **«Пойдёт туда»** — следующая станция его маршрута (`stationRouteOf`).

Пропущенные станции видны сами: стрелка идёт мимо (`POLISH → HEAT 18`, `POLISH → IGU 4`). Skip из офиса — через
его отметки. Ничего не выбрано — стрелок нет.

**Рисунок** — свой SVG без библиотек (`src/erp/views/floor.js`, стили `src/styles/floor.css`).
- 2D — вид сверху. 3D — проекция с поворотом и наклоном мышью, Shift+drag — сдвиг, зум.
- Видимые грани — по углу камеры; порядок — по глубине; длинные блоки (печь, линия IGU) — модулями ≤ 6 м.
- В 3D стены всегда низкие (срез 1.3 м), как в архитектурном макете.
- Подписи — у Working, Waiting и выбранной станции; простой блок приглушён, его код — мелко внутри, если
  влезает. Ширины подписей кешируются, раскладка без наложений, с выносками. На время поворота подписи скрыты.
- На виду только `2D | 3D` и `Edit`; в углу холста `−`, `+`, «вернуть вид».
- Сводка одной строкой: `Fri 10:12 · 6/15 working · 312 waiting · CUT 84`.

**Карточка станции** — клик по станции:
- Период: `Today · Yesterday · 7 days · 30 days · From–To`. По умолчанию Today, выбор помнится на этом ПК.
- **Один день**: Done, Per hour, Waiting now (on N dollies), Last scan N min ago; сколько людей сканировало
  (без имён), брак; столбики по часам.
- **Несколько дней**: итоги за период; столбики по дням; таблица `Date · Done · Per hour · People · Broken`
  (рабочие дни, пустой день — 0); клик по дню — этот день по часам.
- Кнопки `Open screen` (`stationOpen`) и `Orders` (`dashStation`). Без денег.
- Источник — `repWorkFacts` с фильтром по станции: день — `repWorkFacts(day)` (кеш Overview); период —
  `repWorkFacts()` по выбору периода, не при открытии вкладки; долгое — в фоне с процентом.
- В памяти ERP только неархивное (архив — через месяц после отгрузки и оплаты). Период старше — строка
  «Older days are in Reports» и кнопка в Reports. При реализации проверить, уходят ли сканы в архив с заказом и
  есть ли в `reports/sources.js` источник «работа станций по дням».

**Вес и скорость**:
- два модуля порядка 20–30 КБ к файлу 5.8 МБ;
- вкладка ничего не считает, пока закрыта: ни таймеров, ни фона;
- рисует заново только по записи или мыши; 3D считается, только когда включено;
- на экранах станций код Floor не выполняется.

**Порог, честно**: первое открытие стоит столько же, сколько `prodBoard()`. Overview на годе ×4 уже 2.6 с
(HANDOFF, «Открыто»). Порог Floor — «не дольше Overview + 0.1 с на рисунок», поворот 3D без рывков (~150
блоков). Замер в `tools/perf-year.js` с первого PR: строка `'@floor'` в `SCREENS` и ветка в `PERF.screen`.
