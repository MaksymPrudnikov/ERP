## Итог

Исправлены все ошибки, которые удалось воспроизвести в текущем браузерном прототипе. Геометрические эталоны v4.5 не изменены. Набор регрессионных проверок расширен с 38 до 57 тестов; `src/` и собранный `dist/GLASS_ERP.html` проходят один и тот же набор.

## Усиленная проверка импорта

JSON импорт теперь проверяет:

- корневой object и типы известных коллекций;
- дубликаты уровней, станций, Shape и Muntin;
- разрешённый формат station code и entity ID;
- `user.skills` как массив;
- ссылку Muntin на существующий Shape;
- полную нормализацию до изменения рабочей DB.

LocalStorage остаётся best-effort входом старого прототипа: он безопасно нормализуется и откатывается к defaults при критической ошибке. В будущей серверной версии доверять browser state как источнику правды нельзя.

## Регрессионные проверки

57 проверок охватывают:

- эталонную геометрию Shape/Muntin v4.5;
- строгий разбор размеров и overflow;
- запрет второго Width/Height в Muntin;
- невозможные/перекрывающиеся/custom layout;
- уникальность ID;
- повреждённый localStorage и атомарный импорт;
- XSS через значения и идентификаторы;
- пустые справочники после reload;
- RU/EN и защиту пользовательских данных от перевода;
- viewport 390 × 844 без document overflow.

## Что остаётся риском текущей стадии

1. Данные хранятся только в localStorage/JSON: нет общей БД, транзакций, пользователей, server authorization, backup и конкурентной работы.
2. Roles на экране не являются системой доступа. Скрывать прибыль/себестоимость нужно на API/DB уровне.
3. Нет orders/components/routes/WIP event journal, inventory, purchasing, quality, shipping и costing — текущая оболочка остаётся фазой фундамента.
4. Perfect Cut bridge заблокирован реальными входными данными. Формат не выдуман намеренно.
5. Визуальная верификация shop drawing на наборе реальных нестандартных Shape всё ещё нужна; числовые regression tests не проверяют все наложения подписей.
6. Полная production security требует серверного CSP/auth/RLS/rate limit/audit/backup; её нельзя добавить только в single-file HTML.
7. Нельзя математически доказать отсутствие всех будущих ошибок. Результат аудита относится к воспроизведённым сценариям и текущему commit tree.

Глубокая целевая модель и варианты платформы описаны отдельно в `docs/DEEP_ERP_ARCHITECTURE.md`.
