# Users и сервер

Люди и их входы, доступ к разделам, журнал входов и подключение компьютера к серверу (Cloud). Раздел видит тот, у кого в
Users стоит галочка Users, — это администратор.

## Экран

Таблетки **Office** (люди с входом в офис), **Production** (люди с входом на станции), **Sign-in log**, **Cloud** —
рядом число записей. Над таблицей для отмеченного человека **Edit** и **Remove**, справа **Add user**. Таблицы — как в
Sales ([lists.ru.md](lists.ru.md)).

- **Office**: Name, Now (где человек сейчас в системе, иначе — когда был последний раз), Sections, Password (set / not set). Администратор сервера видит ещё колонку
  **Server** — почта входа и «same» / «differs» / «not on server».
- **Production**: No., Name, Now, PIN.

## Человек

У человека два входа, оба необязательны, могут быть оба — например, мастер цеха (владелец, 03.10.2026).

- **Name** — обязательно.
- **Office sign-in · password · sections**:
  - **Password** — от 8 символов. Первый пароль даёт только Users: самому придумать его на экране входа нельзя, иначе
    любой за компьютером займёт чужое имя. Дальше человек меняет свой пароль сам: своё имя внизу меню → **Change
    password** (или **Sign out**).
  - **Server login** — почта входа на сервер, у каждого своя.
  - **Sections** — галочки разделов меню, **All** / **None**. Доступ — «видит / не видит» (выбор владельца): раздела без
    галочки нет в меню, и туда не попасть. Две галочки без своего пункта меню: **Screens** — ставить отчёты на экраны
    станций и людей (Reports → Show on); **Cost & margin** — видеть и править закупочные цены в Data.
- **Station sign-in · number · PIN**: **No.** — личный номер, **PIN** — 4 цифры. «Any station. The office gives the PIN.»
  PIN человек сам не меняет. Снятый PIN сразу заканчивает вход на станции.
- **Save** / **Cancel**. Пароля и PIN в базе нет — только отпечатки. Переход на другую вкладку Users с несохранённой
  карточкой спросит «Discard unsaved changes?».

**Users не запирается**: последнему человеку с галочкой Users её не снять и его не удалить — «Someone must keep Users».
Администратор (галочка Users) видит всё.

## Sign-in log

Входы и выходы: When (по умолчанию 14 дней), Who, What, Where (офис, Station CUT…), Note. Журнал — этого компьютера
(«this computer only»).

## Сервер (Cloud)

Каждый компьютер работает со своей базой в браузере; сервер — общая копия, через которую компьютеры обмениваются
правками. Без сети очередь правок ждёт и переживает F5.

### Подключить компьютер

- Пока компьютер не подключён, внизу экрана — кнопка **Connect server**: маленькое окно Server, Publishable key, Email,
  Password, **Connect**. То же — в Users → Cloud.
- Первое подключение — сразу Download: база браузера заменяется серверной (спросит «Replace this browser database?»).
  Скачать базу может любой участник сервера, не только Users.
- **Один вход**: после подключения ERP входит паролем сервера — отдельный пароль ERP не нужен. Sign out в Cloud — выход и
  из ERP. Станции входят как раньше, номером и PIN.

### Users → Cloud

- **Server**, **Publishable key**, **Email**, **Password**, **Connect**; статус: Not connected, Signed in · почта,
  Connected · имя (· admin). **Check** — проверить связь, **Sign out** — выйти.
- **Sync**: **Upload this database** — эта база становится серверной (сервер пуст, нужен администратор сервера);
  **Download from server** — база этого компьютера заменяется серверной; **Stop sync** — компьютер больше не
  синхронизирует, его база остаётся как есть. Статус: Synced, N waiting, Offline · N waiting.
- **Access** (видит администратор сервера) — какие разделы нужны для чтения и записи каждой таблицы на сервере: Table,
  Read, Write, Edit, ×, **Add rule**, **Save access**, Refresh. «No rule — everyone.» Без раздела человек не получит
  строк таблицы даже в обход экрана.
- **Data** — **Export JSON**; пока синхронизации нет — ещё **Import JSON**, Restore pre-import backup и **Clear
  database**. С сервером их нет: замена базы ушла бы всем. Import и Export — для проверок, рабочие данные живут на
  сервере (владелец, 19.10.2026).

### Права на сервере

Save человека в Users отправляет на сервер его галочки разделов: галочка Users — администратор сервера, без входа в
офис — вход на сервер отключён, сменили почту — прежний вход отключается. Новый пароль у человека с почтой — новый вход
на сервере.

### Что значат надписи внизу экрана

- **Editing here** — эта вкладка пишет в базу. **Editing in another tab** — пишет другая вкладка, здесь только
  смотреть. **Not saved**, **Older version** (вышла новая версия программы) — сказать администратору.
- **Server has a new database · Download** — на сервере новая база (её очистили и залили заново). Синхронизация стоит,
  пока компьютер не нажмёт Download в Users → Cloud: иначе старая база смешалась бы с новой (09.11.2026).
- «Changed on another computer: … Server copy shown.» — кто-то успел раньше: строки этого компьютера вернулись к
  серверной копии. «No access on server: …» — у человека нет раздела для этих записей.
- Справа — размер базы (DB … MB).

### Архив

Завершённое (отгружено и полностью оплачено, через 3 месяца) уходит в архив; с сервером архив живёт только там и
открывается по кнопке, когда его просят (владелец, 22.10 и 01.11.2026).
