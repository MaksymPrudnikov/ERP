Версия 5.313 · 14 ноября 2026 — действия экрана без кода в разметке (`core/actions.js`): Sales, фигуры, списки, общее, Optimization, Production и станции переведены, осталось 958 обработчиков из 2095; Cancel order и Delete заказа — только с галочкой Finance; хендофф — «как устроено сейчас» по разделам, журнал решений — `docs/journal/`.

## Как читать

- Это **как устроено сейчас**. Раздел своей задачи читать целиком; «Общее» — всем.
- Каждое правило владельца — с датой и записью журнала: «Заголовок» (2026-11) значит запись
  `## Заголовок · …` в `docs/journal/2026-11.md`. Найти: `grep -n "^## Заголовок" docs/journal/2026-11.md`.
  Решения из выполненных заданий («решение 27») — `docs/journal/решения-из-заданий.md`.
- Что где лежит в коде — `КАРТА-ПРОЕКТА.md` (таблица «Разделы» и «Все модули» из шапок файлов).
  Шапка модуля — первый комментарий файла: что делает, `IN :`, `OUT:`, затем решения владельца.
- Для людей — руководство `docs/manual/<раздел>.ru.md` / `.en.md`. Этот документ его не повторяет.
- Поведение изменилось — запись сверху в журнал месяца и **правка своего раздела здесь** (переписать, чтобы
  он оставался правдой, а не дописать историю). Тест держит документ до 100 КБ и с разделом на каждую строку
  таблицы «Разделы» в карте.
- Правило владельца здесь — окончательное: если старая запись журнала говорит иначе, действует то, что здесь.
  Сомнение — спросить владельца, а не выводить из кода.

## Общее

**Правила владельца**
- **Без кирпичей.** Не запрещать «по логике данных»: что человек сделал, то и записать; вместо запрета — окно
  с решением человека («… anyway») и запись в журнал (08.10, 11.10 «ничего не блокируем»). Факты человека
  (оплата поставщику, приёмка, Add/Remove склада) записываются без сверки двух ПК — «Исправления после аудита #233–#237» (2026-10).
- **Решение системы — на виду**: «если система приняла решение, то пусть скажет» (05.10).
- **Ничего из функций не ломать** при переделках, числа «до / после» сверять; не снимать возможности «по пути» (29.10, 09.11).
- **Сначала искать готовое**: «зачем строить новое, если есть готовое и правильное» (09.11) — «Стекло фигуры — по режущему прямоугольнику» (2026-11).
- **Интерфейс только на английском**, подсказки — несколько слов; комментарии и документы — по-русски.
- **Стёкла, юниты, листы — только целые** («Whole units only.», 20.10). Сутки 0:00–24:00, без смен (09.10).
- **Все таблицы как Sales** — см. Списки. **Деньги до цента как Spiel** — см. Sales.
- **Движение экрана** вариант F + H: рядом лежащее всплывает, глубже — лист; станциям всё мгновенно (02.11) — «Движение экрана» (2026-11).
- **Не «висит» и не замораживает**: долгое — в фоне с процентом (29.10); пороги скорости на слабом ПК (×4) — скан ≤ 1 с,
  действие офиса ≤ 5 с, экран ≤ 1 с, F5 ≤ 5 с (F5 6,2 с принят 09.11), память ≤ 1 ГБ — `AGENTS.md`, `tools/perf-year.js`.
- Данные в ERP пока тестовые, бухгалтерия на ERP ещё не работает (08.11); пилот параллельно со Spiel — этап 8 плана «до 10».

**Как устроено**
- Один HTML из модулей `src/` в порядке `build/manifest.json`; общее глобальное пространство имён. Разделы
  закрыты API (этап 5): таблицы `SECTION_OWN` (`erp/sections.js`) пишет только свой раздел — Finance, склад,
  Shipping; другие зовут имена из `FIN_API`, `STOCK_API`, `SHIP_API`. Сторож — `test/sections-api.js`.
- База — объект `DB` в памяти, хранится в IndexedDB по записям; запись — одна `storageCommand(fn)`: при отказе
  форма не закрывается, набранное остаётся, повтор пишет один раз. Две вкладки и два ПК — см. Users и сервер.
- Номера `G-0000001` (стекло), `U-0000001` (юнит), `S-0000001` (кусок стока) — 7 цифр минимум, Code 128; высший номер
  хранится и вне базы, не повторяется после старой выгрузки; с сервером — блоками `cloudNumbersReserve`.
- Посчитанное живёт между отрисовками (`READ_KEEP`, `erp/read-scope`), сброс — любая запись и новый день.
- Страница ходит только туда, что в CSP (`build/build.js`): свой сайт, `https://*.supabase.co`, Google Maps; `test/csp.js`.
  `'unsafe-inline'` в `script-src` остаётся, пока в разметке есть обработчики (`onclick="…"`) и пока в
  `dist/GLASS_ERP.html` весь код встроен одним `<script>` — ему нужен `sha256` от сборки (PR 5 задания ниже).
- **Действия экрана без кода в разметке** (`src/core/actions.js`, задание `ЗАДАЧА_CSP_БЕЗ_INLINE.md`, 14.11): кнопка
  несёт имя функции и аргументы данными (`data-on-click`, `data-args-click`), вызывает один слушатель на `document`
  — только функции из реестра (их кладёт туда `onAct` при отрисовке), имя из разметки в `window` не ищется.
  Порядок прежний: от цели вверх, раньше слушателей `document`; `event.stopPropagation()` и `event.currentTarget`
  в действии работают как во встроенном обработчике. Разметку пишет помощник:
  `onclick="salesOrderDelete('${esc(id)}')"` → `${onAct('click',salesOrderDelete,id)}`;
  `oninput="f('name',this.value)"` → `${onAct('input',f,'name',EL_VALUE)}` (метки `EL`, `EVENT`, `EL_VALUE`,
  `EL_CHECKED`, `elData('x')`); `event.stopPropagation();f()` → `onActStop`; `if(event.target===this)f()` →
  `onActSelf`; в строке через `'+'` — `'<b '+onAct('click',f)+'>'`. Аргументы — данные, `esc` для них не нужен.
  Несколько шагов, условие, присваивание — маленькая функция рядом со своим экраном (`salesDraftSet`,
  `salesListDrop`). Код строкой (`${go}`) не передают — передают функцию и аргументы. Переведены: PR 1 — Sales,
  фигуры, списки, общее; PR 2 — Optimization, Production, станции; осталось 958 в 29 файлах
  (`node tools/csp-handlers.js`).
- **Как перевести раздел** (PR 2–5): `node tools/csp-handlers.js --write <файлы>` переводит простые формы и
  печатает остальные «руками» с причиной; `git diff` прочитать по каждому файлу (что проверять — в шапке скрипта);
  функция, которую подменяют на `window[name]`, должна сохранить имя; тесты, искавшие элемент по `[onclick…]`, —
  на `[data-on-click="имя"]`; уменьшить числа в `INLINE_LEFT` (`tools/csp-handlers.js`) — `test/docs.js` сверяет
  список с кодом, новый `onclick` в любом файле красный. Кнопку записи база узнаёт по имени действия
  (`storageLockButtons`): имя новой функции-обёртки должно так же подходить под `save*`, `*Save`, `*Create`, `del*`,
  как прежний текст `onclick`, и не подходить, если прежний не подходил.
- Сторожа: `test/run.js` (все), `test/docs.js` (документы, карта, шапки модулей, `INLINE_LEFT`), `test/actions.js`,
  `test/design-tokens.js`, `test/motion.js`.

## Sales

Заказы и квоты: клиент, PO, Makeup, строки, фигуры, сервисы, цены, статусы, Hold и отмена юнитов, журнал заказа,
бланки. Код `src/erp/sales/`, `src/erp/views/sales*.js`, фигуры `src/modules/shape/`; данные `DB.salesOrder`,
`DB.shapeDef`, `DB.orderEvent`. Руководство `docs/manual/sales.*`.

**Правила владельца**
- **Статусы** New → Verified → Batched → Ready → Picked up / Delivered → Closed; Cancelled. Батч закрывает строку
  (размер, Makeup, фигура, кромка): изменение — новая строка или новый заказ; количество в батче — только вниз, пока
  не порезано (06.10). Строку с живым сканом не менять. Hold и статусы пишутся сразу, без Save (15.09).
- **PO у всех клиентов** (29–30.10): без PO Save — «Enter the Customer PO.»; Verify / батч / выдача старого заказа —
  окно «PO missing» только с Back; квоте и черновику PO не нужен, Convert спрашивает PO. Галочка PO Required ни на что
  не влияет — «Save as Draft и PO у всех» (2026-10).
- **Квота**: ревизии -R1, -R2, отправленная не меняется; Valid until 180 дней; Convert спрашивает ревизию (15.09).
- **Save as Draft** — только в окне выхода; черновик пишется без проверок и ни в чём не участвует (батчи, Shipping,
  деньги, отчёты, склад), строка DRAFT жёлтая (30.10). **Copy** — копия заказа или квоты на 100 % содержания (PO,
  контакт, цены, надбавки), без исполнения; номер — при первом Save (30.10).
- **Деньги до цента как Spiel** (02.11): каждая сторона вверх до целого дюйма; площадь штуки = W×H/144 вверх до
  десятой, не меньше `minArea`; периметр и кромка — от округлённых сторон (фигура — по контуру). Деньги строки точные,
  округление одно — на итоге заказа (`salesCents`). Полцента — вверх. «Счёт до цента как в Spiel» (2026-11).
- **Стекло фигуры** — по режущему прямоугольнику: готовый размер + Safety Border модуля реза по сторонам с косой
  кромкой или дугой (авто: 3–8 мм — 1″, 8–15 мм — 1 1/2″); припуск CNC не входит; CNC — по контуру вверх до дюйма;
  только заказы после правила (09.11). Минимум распорки IGU — **открыт**: ждёт ответа владельца компании, пока общий
  минимум 4 ft² главный, распорка по настоящей площади — Surcharges → By makeup.
- **Цена фиксируется на Save** (снимок `priceBook`): цены Master Data менять можно, сохранённые заказы не меняются;
  Update prices — сегодняшние по прайсам клиента, ручные остаются (20–22.10). Порядок цены — см. Customers.
- **Надбавки** (минимум 4 ft², Triple +50 %, Large +50 % > 60 ft²) — работы Data → Works; в заказе свои числа только
  для этого заказа, 0 = выключить, выключенная нигде не показывается (29.10). Minimum area по макапам — скрыто
  «▸ By makeup» (08.11).
- **Price by hand и Adjustments ±** — на любом этапе, клиент «by hand» не видит (07.10). Отрицательный итог —
  Review required.
- **Delete на любом этапе** (09.10): одно окно последствий; стекло из батчей, PS только этого заказа удаляется,
  оплаты — на депозит, номер не переиспользуется.
- **Cancel order и Delete заказа — только с галочкой Finance** (13.11): без неё — On Hold / Release, ответ «Ask
  Finance to cancel or delete this order.». Квоту и черновик (Draft) Sales удаляет как раньше (тронутый черновик —
  Users / Finance / Optimization). Проверка в командах — `salesCancelDeleteAllowed` в `salesDeleteBlocked` и
  `salesRecordTransitionAllowed` (`erp/sales/lifecycle.js`); в Sales кнопка отвечает этим текстом, в Optimization
  и Shipping — серая.
- **Hold / Cancel units**: юниты выбирает система (непорезанные → меньше работ → закалённые → IGU); цена отмены — по
  работе до Hold (не порезан $0, порезан — отожжённое, после печи — цена лайта, собран — полная); всё отменено:
  $0 → Cancelled, есть сумма → Closed днём отмены (06.10). Решения 12–18 Shipping в `решения-из-заданий.md`.
- **Фигура** живёт только в заказе. **DXF идентичен файлу** (16.10): режется точно по файлу, продаётся с округлением
  к 1/16″; вырез не кругом и сплайн по точкам — отказ; Replace DXF заменяет фигуру и все отверстия. Точка frit — от
  кромок стекла.
- **Ламинат**: плиты на 1/4″ больше, CNC сразу в чистовой (29.09); состав в полосе «LAM 12.76 (6CLEAR + 0.76 EVA-CL +
  6CLEAR)» (08.11). Финиши — две группы (до закалки, после склейки), в группе одна (29.09).
- **Вес** всегда: неизвестное — «Partial» у нас, «≈» на бумаге; ничего — «—» (06.11). Строка Total под Order Lines.
- **Количества работ — в строке при Save** (`line.measure`, 27.10): Save всегда считает по фигуре, отпечаток
  `salesMeasureSig`; строки со старой меткой пересчитываются.
- **Большой заказ** (от 100 строк) сохраняется в фоне с процентом, заказ read-only, «Saved» — после записи (28–29.10).
  Количество > 2000 — вопрос при Save.
- Окно **Production** из Sales (правый клик): где стекло, долли под станцией (08.11). **Cut preview** — только
  просмотр, ничего не пишет (02.10). Сервис «+»: работа Master Data или свой разовый (только деньги, без станции).
- Список Sales: Open и Delete над таблицей; Draft — своя кнопка; колонка Invoice с «Not invoiced · N d»; Created by
  скрыта (11.10); Activity log — коротко (02.10).

**Как устроено**
- Заказ — параметр расчёта: `salesOrderCommercialTotals(order)`, чужой заказ — `salesOrderArg`; `soDraft` только для
  открытого в Sales (этап 4 «до 10»). Расчёт строки `erp/sales/line-metrics`, работы `line-measure`, фигура
  `salesLineCutRect`, Save в фоне `save-job.js`, журнал `order-log.js` (`DB.orderEvent`), Hold `line-hold.js`.
- Экраны Sales, фигуры, списки — без кода в разметке (действия `onAct`, см. Общее): поле шапки заказа пишет в
  черновик через `salesDraftSet(k,v)`, поле строки — `salesLineSet(i,k,v)`, окна Hold — `salesLineHoldField`.
- Цены: `salesBook`, `salesPriceBookOf`; надбавки `surchargeRates`, `salesSurcharges`; минимум `salesMinAreaFor`.
- Сторожа: `test/order-totals.js` + эталоны `order-totals-fixture.js`, `money`, `line-metrics`, `line-measure`,
  `shape-cut-billing`, `order-delete`, `order-draft`, `copy-order`, `unit-cancel`, `batched-line-qty`, `dxf-import`,

## Optimization

Очередь на батч, батчи, свой гильотинный раскрой листов, стикеры, печать батча, станочный экспорт Maver / Disai.
Код `src/erp/production/` (`cut-layout*`, `glass-batches`, `stickers`, `cut-machine-*`), `views/optimization.js`,
`views/cut-layout-ui.js`; данные `DB.glassBatch`, `DB.cutPlan`, `DB.glassPiece`, `DB.stockOffcut`, `DB.cutting`.
**Раскрой правит только Claude с владельцем**; Codex и ChatGPT — нет («я ему не доверяю»). Станочный экспорт —
`docs/MACHINE_EXPORT_STATUS.md`; файлы `cut-machine-*` не трогать (12.11).

**Правила владельца**
- **Свой раскрой**, гильотинный, «будем печатать из нашей оптимизации»; Perfect Cut — только эталон (17.09, 27.09).
  Любая правка раскроя: `node tools/cut-bench.js` — листов не больше Perfect Cut ни на одном батче; ускорять — только
  если листы те же байт в байт (28–29.10).
- **Выбор**: все заказы → меньше ft² → меньше листов → срочные раньше → больший остаток; «мы покупаем листы за каждый
  сквер фут», главный показатель — Used % от площади листов (18.09). «Не размазывай по листам стёкла» (20.09).
  Укладка «полоса → столбик → стопка» на любом числе стёкол (29.10).
- **Trim и Border** — четыре края листа (Trim X снизу, Trim Y слева, Border X сверху, Border Y справа, ноль слева
  внизу), свои у размера листа; Min distance — минимальная полоска отхода (18–22.09). Базовые настройки не менять,
  1/2″ — только руками оператора (05.10).
- **Приоритет как Perfect Cut**: 10 — самый срочный, пусто — без (04.10). Rush / Critical — первыми на резку (11.10).
- **Остаток** — отход, пока его руками не отправили в сток; полезный ≥ 40 × 40″ или ≥ 10 ft²; кусок `S-` в раскрой —
  по галочке, в два батча не идёт (и с двух ПК) (18–20.09, 09.11). Split — одним резом до Border.
- **Build / Reset** как Perfect Cut; собранный раскрой F5 не пересобирает (28.10); Reset порезанного — предупреждение
  (11.10). Пустой последний лист — решает человек: стёкла в новый или открытый батч. Полка «Not on a sheet» — без
  автоматики (19.10). Батч с отменённым / Hold стеклом — Re-optimize, на CUT «Don't cut — batch changed».
- **Номер стекла в батче** — сквозной, не сдвигается; номер листа — свой у каждого стекла («6CLEAR · Sheet 1»)
  (30.10). Батч не хранит копию строки заказа (29.10).
- **Цех видит только оптимизированное**: нет оптимизации — нет номерка — нет в очереди (19.10). Слабые листы ждут
  следующего батча.
- **Очередь без денег и квот**: Glass pcs, Area ft², Priority (07.10). Вид как Sales: действия над отмеченным и правой
  кнопкой, Open — правой кнопкой (03–05.11).
- **DXF** режется точно по файлу, остальное — сетка 1/16″ (19.10); отверстие DXF на столе — только метка.
- **Печать батча** (Stickers, Drawings, Layouts): что печатать — решает человек; лист = страница Letter; куски в сток
  — после стёкол своего листа (04.10, 30.10). Стикер — длины сторон, Free layout.
- **Экспорт**: Disai режет покрытие (мм), Maver — прозрачное (дюймы); пара файлов на лист; Offset листа Maver (до 1″,
  раскрой на уменьшенном, склад списывает настоящий) (24.09, 14.10). Файла нет, если стекло не восстанавливается или
  у Disai глубже 9 уровней.
- Оптимизацию на слабом ПК цех не делает (29.10).

**Как устроено**
- `cut-layout.js`: `cutPlanSteps`, `cutStackSheet`, `cutEffectiveTrim`, `cutGrid16`, `cutSheetCuts` (дерево резов,
  остатки — пустые листья); план `DB.cutPlan` с отпечатком, цифры `cutPlanCounted`; What if и Cut preview — в памяти.
- Батчи `glass-batches.js` (`glassBatchComponents`, Glass ID `G-` при сохранении заказа, `DB.glassPieceSeq`);

  `onAct` (`core/actions.js`, PR 2 задания CSP, 14.11): в `views/cut-layout-ui.js` менялись только обработчики,
  логика раскроя — нет. Cancel order и Delete без Finance серые с подсказкой, в меню правой кнопки их нет.
- Сторожа: `test/cut-layout.js`, `cut-batch`, `cut-offset`, `optimization`, `optimization-fixture`, `glass-batches`,
  `stickers`, `sticker-free-layout`, `sheet-usage`, `sales-cut-estimate`; `tools/cut-bench.js` (данные только у

## Production и станции

Маршрут стекла по станциям, сканы, экраны станций, доски, тара (долли и скиды), Skip, Unbatch.
Код `src/erp/shopfloor/`, `views/station*.js`, `views/production*.js`, `views/carrier*.js`; данные `DB.stationScan`,
`DB.productionRoute`, `DB.carrier`, `DB.carrierEvent`, `DB.carrierCount`. Руководство `docs/manual/production.*`.

**Правила владельца**
- **Где стекло — считается** из последнего скана и маршрута (как в Spil); резка — отметка стекла, не позиции; скан
  без батча с CUT — сделано, в To batch не идёт («чтобы никогда нигде ничего не висело», 08.10).
- **Маршрут** — из работ: работа = станция + цена; станция может быть дважды (`step`); у операций нет запасных
  станций, работа без станции не теряется (лист «NO STATION…»); отверстие — на станцию своего диаметра (22.10).
- **Экран станции** без меню ERP, скан всегда в фокусе, «1234» = G-0001234; Undo — только последнего; Board — только
  своя станция, без чужих имён и $ (09.10). Вход — номер и PIN.
- **Без кирпичей на станции**: пропущенная станция — вопрос «EDGES DONE?», не запрет; стекло едет не туда — жёлтая
  полоса и звук, скан пишется, исправить сканом тары или «✓ Keep» (07.10); Hold — SET ASIDE.
- **Тара** DL, DA, SL, SA: «сначала скан тары, потом то, что на ней»; скан без тары засчитан, следующая тара забирает
  («WHICH DOLLY?»); **стекло без тары ничего не блокирует** (07.10, 30.10). Puts on: базово Dolly, IGU «—», SHIPR —
  Skid. Новую тару регистрирует рабочий, номер даёт система и не повторяет; Empty — два нажатия и Undo; Count не
  двигает стекло (30.10). Окно долли/скида — №1 всегда сверху (03.11).
- **IGU**: любой лайт позиции с любым, тип и размер — по Makeup; стикер юнита печатается сам при закрытии сборки;
  после IGU юнит едет одним сканом U-; человек на сушке сканирует юнит и скид — это Shipping ready (07.10).
- **Recut — в любой момент**, после IGU — весь юнит; пара Recut того же размера; ламинат до склейки — одна плита,
  склеенный — обе (11.10). См. Quality.
- **Skip — всегда** (08.10): Hold снимается на время и возвращается; отказ — только нечего делать или день в
  будущем; делают Users / Finance; цели — любая станция, Picked up, Delivered. **Unbatch order** — Users / Finance,
  Undo нет («несёт ответственность сам», 09.10).
- Production не показывает заказ, всё стекло которого уехало (01.11). Print drawing — на любой станции.

## Shipping

Ready по скану, packing slip (PS), погрузка на SHIP, частичная отгрузка и бэкордер, Delivery (машины, км), скиды у
клиентов, выдача у стойки. Код `src/erp/shipping/`, `views/shipping*.js`, `views/delivery.js`, `views/skids.js`,
`views/station-shipping.js`; данные `DB.shipment`, `DB.truck`, `DB.tripKm`, `DB.skidReturn`. Решения задания —
`решения-из-заданий.md` → Shipping (1–32 и «Чего не делать»). Свои таблицы пишет только Shipping, другие зовут
имена `SHIP_API` (`shipping/api.js`); запись — `shipPersist` / `shipOffice`; снятие с батча правит PS командой
`shippingUnbatchItems` — «План «до 10», этап 5: склад и Shipping» (2026-11).

**Правила владельца**
- **Отгрузка = PS**: один клиент и адрес, заказов сколько угодно, разделы по заказам; `PS-0001`, Code 128; **цен
  на PS нет** (05.10). В PS — только отмеченные заказы; без выбора — все с готовым стеклом (06.10, 02.11).
- **Ready — по скану SHIPR**, без кнопки; «18 / 20 ready»; Ready — плоский список (07.11). Микс на SHIPR — норма.
- **Погрузка**: офис открывает рейс, водитель выбирает скиды, скан скида на SHIP добавляет его в PS; «Ship» —
  едет отсканированное, остальное остаётся в Ready (06.10, 11.10). Скид другого клиента — в свой PS с жёлтой
  полосой («зачем блокировать», 07.10); микс целиком не грузится. Очерёдность по просьбе клиента — офис ставит
  1, 2, 3 («клиент прав»).
- **Долг**: при создании PS и печати — окно Take payment / Print anyway; cash с долгом перед Ship — Back · Load
  anyway · Take payment; кредитных не спрашивает; **стекло выдают несмотря на долг**, подтверждает печатающий
  (12.11) — см. Finance. Hold: не грузили — Back / Edit, погрузили — Ship anyway (11.10).
- **Delivered** — скан подписанного PS в офисе; номер вводят руками: `212`, `ps 212`, `PS-0212` (02.11). Бэкордер —
  тот же заказ, Partially shipped; отмена на бумаге PS обязательна.
- **Delivery**: у машины на день остановки по порядку и время; номера рейса нет; водитель один; км — Google
  Directions, ответ по сменившемуся маршруту не пишется (06.10, 08.11).
- **Скиды**: уезжает, только если на нём нет чужого; самовывоз увозит скид, погруженный сканом; возврат — скан на
  любой станции; обмен «Skid from ABC» — чужой получает наш код, наш самый давний списывается (06.10, 30.10).
- **У стойки**: заказ по номеру (Order | PO раздельно, номер точно, PO по части), Pickup PS одного заказа (06.10).
- Лист скида: таблица по заказу, внутри порядок укладки, QR — в правом верхнем углу (05.11). Shipments — вид NOW,
  день — кнопка Date (05.11). Клиенту — Name стекла.
- Не делать: суммы на PS, деньги за скиды, экран водителя, карты.

**Как устроено**

## Finance

Оплаты, разнесение, возвраты, условия и сроки оплаты, счёт (Invoice), выписка (Statement), журнал денег =
файл QuickBooks. Код `src/erp/finance/` (`api.js`, `ledger.js`, `data.js`, `print.js`), `views/finance*.js`; данные
`DB.receipt`, `DB.refund`, `DB.financeTerms`, `DB.financeEvent`, `DB.financeExport*`. Руководство
`docs/manual/finance.*`. Этап 5 «до 10»: Finance — единственный писатель денег (#462).

**Правила владельца**
- **Деньги вносит только бухгалтер** (Finance). Sales при выдаче кладёт недостающие деньги с листом, водитель отдаёт
  чек (12.11). **Стекло выдают с долгом** «несмотря ни на что»: подтверждает тот, кто печатает; нажатие — в журнал
  заказа («Released with balance due»), без новых колонок и меток (12.11).
- **Invoice** — один на заказ после последнего юнита; номер = заказ; дата = день выдачи, от неё Net; PAID на бланке
  (07.10). Оплаты каждая строкой (Deposit до дня счёта, Payment с него), Credits раздельно, Balance — по этому
  заказу; кредит (бой, скидка после счёта) — Adjustments − (06.11). Счёт не удаляется — исправляют заказ. Наш бланк
  лучше Spiel — доделывать наш.
- **Срок оплаты сам**: billing — вписанная дата или день выдачи; due — явная, или billing + Net (credit), или день
  выдачи (cash); просрочка — со следующего дня; производственный Due Date — не срок оплаты (28.09). Условия
  фиксируются при сохранении заказа.
- **Allocate как Spiel**, вариант D (Debit | Credit, итог строкой, раскрытие связей); действия Accounts — без захода
  в клиента, кнопкой при галочке и правым кликом (06–07.11). Вторая оплата сверх долга с другого ПК — отказ (09.11).
- **Statement**: период From · To (по умолчанию 1-е прошлого месяца — сегодня); Due now — дата «up to», просроченное
  всегда к оплате (07.11); выписка с архивом та же; галочка Invoices — все счета периода одним PDF (22.10).
- **Payments = файл QuickBooks**: бухгалтер видит всё, что уйдёт в QuickBooks; QuickBooks «только новое» (новые,
  Corrected, Voided), Last file — те же байты; счета до 7.10.2026 не выгружаются (07.10, 08.11). После первой
  выгрузки заказ не уходит в архив, пока его деньги не выгружены (08.11). CSV в ERP — только для QuickBooks.
- **Валюта**: клиенты платят CAD, USD клиента — суммой CAD банка; ручной пересчёт по дню оплаты — правило владельца;
  смена валюты оплаченного заказа снимает оплаты в другой валюте на счёт клиента (28.09, 08.11).
- Способы: Cash, Cheque, E-transfer, Debit, Credit card (+2.34 % при карте). Возврат — только из свободного остатка;
  отмена или Delete заказа — оплаты на депозит. Отрицательный итог — Review required.
- Оплаты читают Finance и Sales (продавец видит, сколько оплачено), пишет только Finance; Save заказа без галочки
  Finance проходит (24.10).
- **Отменить или удалить заказ может только Finance** (13.11): «если нет — можно только отправить на On Hold»;
  отмена переносит оплаты на депозит (`finReleaseOrder`). Как устроено — Sales.

**Как устроено**
- Таблицы `FIN_OWN` (receipt, refund, financeTerms, financeEvent, financeExport, financeExportBatch, referrer,
  referrerPayout) пишет только `erp/finance/*`; остальные разделы зовут имена `FIN_API` (`erp/finance/api.js`);
  права в командах — `finNeedAccess`. Общий сторож трёх разделов — `erp/sections.js` и `test/sections-api.js`
  («Outside section: …»).
- `finance/ledger.js`: `finBillingDate`, `finPaymentDue`, `finAllocate` / `finUnallocate`, журнал
  `finJournalEntries`, `finExportPending`; итоги заказа `finOrderTotals` хранит `finTotalsKeep`; архивный заказ
  сначала возвращается в работу (`finBringBack`). Номера возврата RF- — с сервера.
- Сторожа: `test/finance*.js`, `fin-journal`, `invoice`, `money`, `order-totals`.

**Открыто**: формат QuickBooks Online / Desktop (IIF) — у бухгалтера; оплата датой в будущем принимается.

## Хранение и архив

База в IndexedDB по записям, запись командой, вкладки, Export / Import, архив. Код `src/erp/storage.js`,
`storage-records.js`, `archive.js`, `read-scope.js`; данные — все таблицы, архив — склад `cold` и сервер.

**Правила владельца**
- **Главное — не потерять введённое** (29.10). Главная вкладка — последняя открытая, остальные не пишут;
  вкладка с неудавшейся записью держит её до Retry save или Export (22.10).
- **Архив**: уходит заказ, отгруженный целиком и оплаченный без долга (или отменённый без денег), через **месяц**
  после последнего события (`ARCHIVE_MONTHS=1`, 01.11; прежние «3 месяца» от 22.10 заменены). Hold не уходит, NCR с
  исходным — вместе, квоты — группой ревизий, просроченный долг не уходит, невыгруженный в QuickBooks — не уходит.
- **Архив только на сервере** («строй архитектуру под сервер», 01.11): завершённое не загружается, открывается по
  клику; заказ из архива у кого есть Sales — возвращается в работу и правится; в Sales строка серая Archived.
- Настоящая база поверх тестовой — отказ; Clear database — только администратор (21.10). Испытания — Chrome или
  Edge (Safari стирает сайт через 7 дней). JSON Import / Export — для тестов.
- F5 6,2 с на слабом ПК (×4) принят (09.11). Цифры прежней версии пересчитываются в простое, F5 их не ждёт.

**Как устроено**: запись `{tbl, id, seq, data}`, `storageCommand(fn, scope)` пишет только изменённое,
`storageFlush`; отказ — «Not saved…» и Retry; Export v2 — `glazing_system_data.ndjson` построчно; архив
`archive.js` (`archiveDue`, `archiveAuto` пачками по 20 при пустой очереди, `archiveFloor` — номера не повторяются,
`archiveReturn`, `archiveOpen`); указатели `readScope` / `readMemo`. Сторожа: `test/storage-records.js`,
`storage-cold`, `archive`, `base-start`, `read-scope`, `narrow-write`.
