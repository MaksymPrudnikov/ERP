Перед кодом — `AGENTS.md` и раздел «Как вести себя с проектом» в начале
`docs/ДЛЯ_ЧАТГПТ.md`. Раскрой (`cut-layout*.js`) этот этап не меняет: склад
только читает планы раскроя. Единственная правка рядом с раскроем — подсказка
в окне Build (PR 3), алгоритм не трогать.

**Порядок: четыре PR, по одному.** PR → картинки владельцу (`npm run shot`,
файлом) → зелёный CI → слить → следующий. Факт цеха, которого нет ниже, —
спросить владельца ситуацией с вариантами, не придумывать.

## Главное правило

«Всё флексибл и без кирпичей»: склад **записывает, что было, и
предупреждает**, но ничего не запрещает. Отрицательный остаток разрешён и
виден красным. Ошибка исправляется встречной записью (кто, когда), а не
удалением. Всё считается автоматически — ручных бумажных процедур не
предлагать. Интерфейс на английском, подсказки — несколько слов.

## Решения владельца · 14 октября 2026

1. **Объём — листы стекла и остатки S-.** «Давай сначала построим
   инвентаризацию листов, она самая важная, потом материалы». Материалы позже:
   спейсер — в погонных футах (расход по периметру собранных юнитов, отдельный
   разговор). PIB и силикон по весу — «не готов, большой процент потерь и
   утилизации» — не считать. Стекло без галочки «We cut it» (COG,
   `glassProduct.cut===false`) на склад не идёт.
2. **Два числа у каждого стекла+размера.**
   - **On rack** — физически на пирамиде. Уменьшается, когда лист реально
     режут (первый скан на CUT любого стекла с этого листа) или ломают на
     столе (Sheet broke).
   - **Free** — свободно. Уменьшается уже при **Build** батча: лист занят
     раскроем («По Build»).
   - **Reserved** = собрано, но не порезано = On rack − Free.
   Пример владельца: B-0021 собран, 5 листов 6CLEAR 130×96, резать не начали;
   Андрей считает пирамиду — 18 листов. Экран: «On rack 18 · reserved
   B-0021: 5 · Free 13». Пересчёт сверяется с On rack, минимум — с Free.
3. **Приход — только реальные листы.** «Листы будут добавлены в
   инвентаризацию только после того, как оптимизатор или тот, кто работает в
   purchasing, внесёт реальное количество полученных стёкол; до этого ничего
   не меняется».
   - Строка приёмки в листах (`unit` sheet): пришло − бой.
   - В блоках: вписанное **Sheets** (`actualSheets`) − бой (`damagedSheets`);
     пока Sheets пустое — на склад 0, строка приёмки и дашборд подсвечивают
     «Enter sheets».
   - Отмена приёмки (`voidAt`) или правка — склад пересчитывается сам.
   - Строки замены разбитого (`replacement`) — тоже приход.
4. **Пересчёт вводит офис** (Inventory → Count): фактическое число по
   стеклу+размеру; разница — корректировка «было → стало», кто и когда. Старт
   — первый пересчёт каждого стекла+размера; до него в строке «Not counted».
   Владелец очистил свою базу — начинает с нуля.
5. **Минимум — вручную** у стекла+размера: «заказы не линейные, некоторые
   стёкла стоят по 2 года, никто не заказывает». Free ниже минимума — красным,
   фильтр Below minimum. Темпа, прогноза и «заказать до» здесь нет.
6. **Build при нехватке — предупреждение:** «need 5 · free 2», Build
   делается, Free уходит в минус.
7. **Один остаток на стекло+размер**, от любого поставщика. Другой источник
   владелец заводит отдельным стеклом («China 6mm Clear»), чтобы не сбить склад.
8. **Undo Sheet broke** — в журнале склада: встречная запись, лист вернулся,
   видно кто и когда отменил. (Отмену слома владелец откладывал до этого этапа
   02.10.2026.)
9. **Новый раздел меню Inventory**, своя галочка в Users. «Нужен дашборд для
   инвентаризации, активный, с фильтрами».
10. **Остатки S-** — своя часть Inventory, «так же, как и самих листов»:
    дашборд и пересчёт. Optimization → Stock остаётся как есть.
11. **Симуляция** — файл для Import JSON, «сделай больше, чтобы можно было
    поклацать».

Ответы владельца в начале PR 1 (14 октября 2026):

## Откуда склад берёт числа

**Остаток не хранится числом — он считается из фактов**, как балансы
Purchasing (`purReceived` в `src/erp/purchasing/receiving.js`) и журнал листов
(`sheetUsageRows` в `src/erp/production/sheet-usage.js`). Так отмена приёмки,
Unbatch, Reset и пересборка раскроя сами исправляют склад.

**Ключ строки:** код стекла + размер листа «длинная × короткая», округление
`cutRound` (1/16″) — как ключ размера в `sheetUsageRows`. У приёмки код —
`productCode` (или код продукта по `productId`), размер — `widthIn` /
`heightIn` строки приёмки; у раскроя — `group.glass` и `sheet.size || group.sheet`.

| Факт | Откуда | On rack | Free |
|---|---|---|---|
| Приход | `DB.purchaseReceipt` без `voidAt`, строки `kind` glass / sheet с размером | + | + |
| Build | `DB.cutPlan` (без `reset`) активного батча: лист ещё не порезан | — | − |
| Порезан | лист раскладки, с которого есть скан CUT любого его стекла: скан записывает лист (`sheet` в `DB.stationScan`, `invScanSheet`); скан, снятый Unbatch или Delete заказа, — всё равно рез, Undo скана — нет | − | (уже −) |
| Сломан на столе | `DB.sheetBreak` (батч, стекло, лист, w, h, by, at) без отмены | − | − |
| Пересчёт, списание, Undo слома | новый журнал `DB.inventoryEvent` | ± | ± |
| Минимум | новое `DB.inventoryMin` (ключ → число) | | |

Правила:
- Порезанный лист — расход и после Reset, Unbatch и Delete заказа;
  непорезанный при Reset / Unbatch освобождается. Поправка PR 1: Reset
  сохраняет только остатки S- порезанных листов (v5.166), а сами листы
  уходят из раскладки, — поэтому лист записывается в скан CUT.
- Кусок S-, взятый в раскрой, на листы не влияет. Поправка PR 2: со стока
  он не снимается (`DB.stockOffcut` остаётся «stock», Optimization → Stock
  показывает «In B-…»); склад считает его ушедшим по скану CUT его листа.
- Прикидка раскроя из Sales (EST) ничего не пишет — на склад не влияет.
- Приёмка без размера листа — строка «Size missing» в дашборде, не ключуется
  молча в чужой размер.
- Отрицательный остаток разрешён.

## Экраны (раздел Inventory)

Меню разделов — как `purNav` в Purchasing (одна кнопка с выпадающим списком).

- **Sheets — дашборд.** Плитки: стёкол, листов On rack, Free, Below minimum,
  Negative, Not counted, «блоков без пересчёта». Таблица: Glass, Code, mm,
  Size, On rack, Reserved, Free, Minimum (правится в строке), At supplier
  (Held at supplier — `purHeldGroups`), On order (PO, не пришло —
  `purWaitingRows(false)`), Last count (когда, кто), Status (OK / Below
  minimum / Negative / Not counted). Фильтры колонок и чипы статусов — как в
  Sales. Строка открывает журнал этого стекла: приход (GR-…), Build (B-…), Cut,
  Sheet broke с Undo, Count.
- **Count.** Таблица всех стекло+размер с On rack и полем Counted. Save пишет
  только изменённые строки одной командой. Write off — списание с причиной
  (разбили на стеллаже, брак).
- **Offcuts — остатки S-.** Дашборд: штук, ft², по стеклу, возраст на стеллаже.
  Пересчёт: отметить «not found» → списан (кто, когда).
- **Journal.** Все движения, фильтры: дата, стекло, вид, кто.

Вне раздела:
- **Optimization, раскрой:** при Build и в выборе размеров — «need 5 · free 2»
  по размеру листа. Только подсказка.
- **Purchasing, приёмка:** строка блоков без Sheets — «Enter sheets».

## Как писать

- Модули: `src/erp/inventory/*.js` (данные, расчёт, команды) и
  `src/erp/views/inventory*.js` (экраны), каждый файл — в
  `build/manifest.json`; нормализация — в `src/erp/storage.js` рядом с
  `normalizePurchasing…`.
- Запись — одной `storageCommand`; история — кто и когда (`orderLogActor`,
  `salesUid`), как `purRecordEvent`.
- Списки — движок Sales: хуки scope / columns / defaults в
  `src/erp/views/sales-list-ui.js`, как сделал Purchasing
  (`purListScope`, `purListColumns`, `purListDefaults`).
- Проверки каждого PR: `test/inventory*.js`, подключить в `test/run.js`.
  Сценарии: приёмка листами / блоками с Sheets и без / бой / Undo приёмки;
  Build → Reserved, скан CUT → On rack; Reset и Unbatch до и после реза; Sheet
  broke и его Undo; пересчёт и минимум; COG не на складе; Export / Import.
- Каждый PR: число проверок в первом абзаце `README.md`, раздел сверху в
  хендоффе, версии карты и инструкции, `npm run build:web` и закоммитить
  `src/index.html`, `npm run test:snap -- --dist`, пуш только
  `node tools/prepush.js`, PR — `gh pr create --base main --head <ветка>`.
- Картинки «сейчас / после» — `npm run shot` (ключи: `node tools/shot.js
  --help`), владельцу файлом.

## Не делать в этом этапе

- Материалы (спейсер, PIB, силикон, газ) — позже, отдельно.
- Темп расхода, прогноз, «заказать до» для листов — владелец выбрал минимум.
- Запрет Build при нехватке, обязательные поля, бумажные процедуры.
- Изменения алгоритма раскроя.
