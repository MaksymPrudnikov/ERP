ничего не описывает по существу — он только указывает на нужный документ.

## Правило номер один: хендоф один

Управляющий документ проекта — **`docs/GLASS_ERP_HANDOFF.md`**, и он
**единственный**.

- Вторых копий не заводить. Ни в корне, ни под другим именем, ни «временно».
  Два документа с разной нумерацией уже дважды приводили к потере правок:
  сначала с планом (21 августа), потом с самим хендофом (1 сентября).
- Правка идёт **в конец шапки и новым разделом сверху**, старые разделы не
  переписываются — по ним читают историю решений.
- **Версию поднимать всегда.** Номер — единственное, по чему видно, какой
  документ свежее. Текущая версия **3.8**.

## Как правильно обновлять

1. **Правится модуль в `src/`, а не `dist/`.** Собранный HTML руками не
   трогают никогда — его перезаписывает сборка.
2. Новый файл модуля обязательно вносится в `build/manifest.json`, иначе он
   молча не подключится. Проверка: `node build/check-manifest.js`.
3. Пересобрать: `node build/build.js`.
4. Прогнать тесты **двумя способами** — CI гоняет второй, и расхождение
   всплывёт только там:
   - `node test/run.js` — по исходникам;
   - `TARGET=dist node test/run.js` — по собранному файлу.
5. Обновить `docs/GLASS_ERP_HANDOFF.md`: новый раздел сверху, версия поднята.
6. Работать в отдельной ветке и заливать через PR. `main` меняется только
   мержем; автосборка `dist` в `main` делается CI, не руками.

### Конфликт в `dist/GLASS_ERP.html` — это норма, чинится пересборкой

Робот пересобирает `dist` в `main` после каждого вливания. У ветки, открытой
дольше одного мержа, лежит своя сборка того же файла — обе стороны переписали
один и тот же порождаемый файл. Так будет каждый раз; это не поломка.

**Автослияние для этого файла запрещено** в `.gitattributes` (`-merge`), и это
важнее, чем кажется. Без запрета git сводит две сборки текстом и молча выдаёт
файл, не соответствующий ни одной стороне: на проверке двух веток, правивших
разные css-модули, в слитом `dist` осталась одна правка из двух — а файл при
этом выглядел целым. С запретом git честно останавливается на конфликте.

Разрешение одно — пересобрать из уже слитых исходников:

```bash
git merge origin/main
node build/build.js && git add dist/GLASS_ERP.html
git commit
```

**Пересобирать только ПОСЛЕ слияния.** Драйвер слияния для этого не годится и
намеренно не заведён: git вызывает его раньше, чем кладёт слитые исходники в
рабочее дерево, и сборка идёт по неполным файлам. Проверено — драйвер собрал
`dist` без одной из правок.

Последний рубеж — CI: он сам пересобирает `dist` из модулей, гоняет по нему
тесты, и в `main` коммитит канонический файл. Поэтому устаревший `dist` в ветке
не опасен; опасен молча склеенный.

На GitHub кнопка слияния всё равно покажет «Can't automatically merge» — там
помогает только влить ветку раньше, чем робот тронет `dist`. Короткие PR дешевле
длинных.

### Чего не делать

- Не заводить вторую копию хендофа, плана или любого управляющего документа.
- Не удалять файлы в `src/` — заменять содержимым.
- Не создавать второй разбор дюймов, второй путь печати, второй переключатель
  обработки кромки. Всё это уже есть в одном экземпляре, и дубли расходятся.
